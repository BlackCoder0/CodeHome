# 子模块验证报告

本文用于对照 `全面升级.md` 与当前 `CODEX升级/` 原型页，确认哪些设计要求已经被独立验证，哪些只是部分覆盖，哪些仍缺少对应实验页。

## 1. 结论总览

当前已经有明确验证页的主线有 7 条：

1. 全站统一深度参数系统
2. 全站连续海域背景
3. `Projects` 顶部跳水 runtime 状态机
4. `Hobbies` 左侧 3D 可交互样本舱的基础交互
5. `Contact` 的海底遗迹 + 信号场方向
6. `About` 左灯 + 右上轨道 + 下方内容结构
7. `Bangumi` 左筛选 + 归档带 + 观察窗详情结构

其中真正可以视为“验证完成”的，只有前 3 条。  
`Hobbies`、`Contact`、`About`、`Bangumi` 目前都还是结构或方向验证，还没有收敛到可以直接接入 `src/` 的程度。

---

## 2. 已验证完成

### 2.1 全站统一深度参数系统

对应原型：

- `project-global-depth-driver.html`

验证结果：

- 已验证“滚动进度 -> 全局深度参数”的单一驱动关系。
- 已验证 `Projects / Hobbies / Bangumi / About / Contact` 五段可以通过同一套参数渐变过渡。
- 已验证参数项覆盖了 `depth / surfaceLight / waterTint / mistLevel / particleDensity / creatureDensity / giantPresence / ruinSignalLevel` 这类核心环境变量。

结论：

- 这部分已经足够作为后续全局 driver 的直接参考。
- 不需要再重复开新页做同类实验。

### 2.2 全站连续海域背景

对应原型：

- `project-ocean-root-background.html`

验证结果：

- 已验证 section 作为透明壳层叠在统一海域背景上仍然成立。
- 已验证从 `Projects` 到 `Contact` 的纵深切换不会硬断。
- 已验证 `Bangumi` 档案带、`About` 观测室外部、`Contact` 遗迹信号层都可以作为同一背景系统中的不同深度状态存在。

结论：

- 这部分已经足够作为全局背景承载层的参考页。
- 后续重点应是“接入真实 section”，不是再做一版背景概念页。

### 2.3 `Projects` 顶部跳水 runtime 状态机

对应原型：

- `project-projects-dive-runtime.html`

验证结果：

- 已明确拆出 `approach / takeoff / airborne / impact / underwater / reveal` 六段状态。
- 已验证整段由滚动驱动，而不是自动播放时间轴。
- 已验证入水事件、水花触发、卡片出现时机可以由状态控制。
- 已验证卡片不能早于入水后的缓冲阶段冒出来。

结论：

- 这部分已经完成“机制验证”。
- 后续应基于它替换视觉，不应推翻状态机重新做。

---

## 3. 部分验证

### 3.1 `Hobbies` 样本舱

对应原型：

- `project-hobbies-sample-cabin.html`

已验证：

- 左侧应升级为真实 3D 可交互模块。
- 样本舱视口、拖拽旋转、单独观察逻辑是成立的。
- “左侧是独立样本观察舱，不只是嵌一个页面”这个方向成立。

未验证完：

- 当前模型语义是 `Helicopter Wreck`，和文档锁定的“舱体残骸 / 船体残骸为主，生物组织反向生长其上”并不一致。
- 还没有验证“文明遗体为主，不是怪物百科”的边界。
- 还没有验证“样本舱容器材质”和右侧档案阅读器之间的关系。

结论：

- 这页只能证明“3D 可交互样本舱值得做”。
- 不能证明当前形态语言已经定稿。

### 3.2 `Contact` 遗迹信号场

对应原型：

- `project-contact-ruins-signal-field.html`

已验证：

- 现有 `Contact` 点阵逻辑可以被改写成海底地形、遗迹轮廓和信号回声。
- “海底前文明遗迹层”这个方向成立。
- 指针排斥和回声式交互可以保留，不必推翻重写。

未验证完：

- 还没有和真实 `Contact.tsx` 的左右布局、留言板、友链、统计面板结合。
- 还没有验证“终端语义”是否能替代现有偏展板/偏公告栏的皮肤。
- 还没有单独验证移动端遗迹结构与桌面端结构的统一方式。

结论：

- 这页是方向页，不是接入页。
- 后续还需要一版更贴近真实 `Contact` 结构的 runtime 原型。

## 4. 当前缺失的独立验证

下面这些点在 `全面升级.md` 里已经明确，但当前 `CODEX升级/` 没有对应的独立验证页，或者只在综合页里被顺带碰到，不能算验证完成。

文档要求：

- `Projects` 顶部跳水只是入口
- 项目卡片、技术栈、状态标签、详情层都要服从浅海工作层的容器语言
- 默认包裹强度为“中包裹偏强”

当前状态：

- 已验证跳水 runtime
- 未独立验证项目卡片层的容器和包裹强度

结论：

- **仍需补验证页。**

建议原型名：

- `project-projects-shell-wrap.html`

### 4.2 `Projects` 顶部技术拆分

文档剩余项明确要求：

- 哪部分用 DOM / CSS 完成
- 哪部分用 canvas 完成
- 滚动进度与动作帧如何映射

当前状态：

- `project-projects-dive-runtime.html` 已验证状态机
- 但还没把实现边界拆成可接入的技术方案

结论：

- **还差一份技术拆分验证。**

建议原型名：

- `project-projects-dive-tech-split.md` 或独立实验页

### 4.3 `Hobbies` 舱体残骸形态语言

文档剩余项明确要求：

- 小型单人舱残骸？
- 大型船壳截面？
- 深海设备外壳？
- 半器官化的舱体结构？

当前状态：

- 只有一个直升机残骸方向页
- 没有把“残骸类型”做成独立对比验证

结论：

- **仍需补验证页。**

建议原型名：

- `project-hobbies-hull-morphology.html`

### 4.4 各区容器形制与动效层级

文档剩余项明确要求：

- 各 section 容器长什么样
- 各区动效谁先谁后
- 哪些地方是主动效，哪些只做陪衬

当前状态：

- 各原型都是单点验证
- 还没有一页专门验证全站容器家族和动效层级

结论：

- **仍需补验证页。**

- `project-section-shell-language.html`

## 5. 已新增但仍未完成接入的验证页

### 5.1 `About` 私人观察角

对应原型：

- `project-about-observatory-room.html`

已验证：

- `About.tsx` 的真实三段结构可以被海洋语义重新解释。
- 左灯负责局部暖域，右上轨道负责私人联系装置，下方内容继续承担阅读主体。
- 移动端顺序仍保持 `PlanetSystem -> 文案 -> DeskLamp3D -> 内容`。

未验证完：

- 当前仍是壳层与关系验证，不是最终真实组件接入版。
- 还没验证真实灯光切换与内容动画联动。

### 5.2 `Bangumi` 中层观察档案带

文档要求：

- 这是“中层海域的观察档案带”
- 详情层更像观察窗，不是普通 modal
- 默认环境包裹强度为“中到强包裹”
- 容器应克制，避免与封面打架

当前状态：

- 已有专门验证页。
- 真实 `Bangumi.tsx` 仍偏“横向媒体卡带 + 弹窗详情”，还没真正接入这套三区结构。

已验证：

- 左筛选层、中间归档带、右侧观察窗详情这三个层级可以成立。
- 详情层固定在当前 section 内，不必做普通 modal。
- 内容包裹强度可以提升到“中到强”，而不压坏可读性。

未验证完：

- 还没把真实 API 数据状态、加载态、错误态和这套结构接起来。
- 还没验证真实图片比例和长文简介在观察窗里的占位。

## 6. 验证优先级

如果只按“最影响后续接入”的顺序排，建议这样做：

1. `Projects` 展示层环境包裹
2. `Hobbies` 舱体残骸形态语言
3. `Contact` 更贴近真实结构的 runtime
4. 全站容器形制与动效层级

原因：

- `About` 和 `Bangumi` 已补上结构验证页，所以优先级从“必须先补”降为“后续接入”。
- `Contact` 已有方向页，所以可以稍后。
- 容器形制与动效层级应放在几个关键 section 语义稳定之后统一收口。

---

## 7. 最终判断

当前状态不是“没有验证”，而是：

- 全局海洋系统：**主干已验证**
- `Projects` 顶部 runtime：**机制已验证**
- `About` / `Bangumi`：**结构已验证，仍未接入真实组件**
- `Hobbies` / `Contact`：**方向已验证，形态未定**
- 全站容器家族与动效层级：**还没单独验证**

因此，下一步最合理的动作不是再做一版综合大页，而是继续补缺的独立验证页。
